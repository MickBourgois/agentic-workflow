# Changelog

## 0.8.0 — 2026-11-16

- Separate evidenced P0-P2 blockers from optional P2-P3 suggestions across review,
  orchestration, rework and PR-thread triage. Approval with suggestions is valid.
- Reject contradictory approvals, P3 blockers, incomplete findings and omission
  of independent blockers from the deduplicated rework handoff.
- Preserve settled scope/design decisions on re-review; newly discovered concrete
  defects still block. Keep two reworks by default and independent critical slots.
- Use six core hardening sections with conditional risk detail; justify mandatory
  additions and keep optional ideas outside acceptance criteria.
- Run relevant lint/types before review. Source CI cancels superseded runs and
  avoids duplicate feature-branch push/PR runs. Consumer final gates are unchanged.
- Keep state format 2 and installer ownership/checksum rules. Existing runtime
  evidence is preserved; unresolved legacy findings require reconciliation.

## 0.7.1 — 2026-11-15

- Retire the `harden-project-cards` Skill and Claude command alias. Use `harden-card`.
- Installer updates back up pristine legacy adapters and preserve modified ones as conflicts.

## 0.7.0 — 2026-11-12

- Run sufficient recorded focused checks before both initial and rework reviews;
  preserve stricter project/card requirements such as a build before commit.
- Mark code reviews as `code_and_focused_checks`. Keep risk classification,
  independent critical review slots and bounded rework unchanged.
- Add `reviews_approved` and VALIDATING between review and delivery approval;
  execute and bind the required project gate only after all code approvals.
  `review_approved` now accepts the final gate from VALIDATING, not REVIEWING.
- Require exact-base/head final gate records even without a project verifier.
  Reverify bindings and compare saved hashes on shipping, reusing valid proof
  without another gate run. Project profile selection remains opt-in/fail-closed.
- Use local state format 2 and preserve legacy format 1 receipts/checkpoints.
  Document evidence recovery and human stops for incomplete legacy deliveries.
- Distribution manifests and SHA-256 hashes are generated by install/update;
  no consumer installation, public release, merge or deployment is part of this preparation.
