# Changelog

## 0.7.0 — 2026-11-12

- Run sufficient recorded focused checks before both initial and rework reviews;
  preserve stricter project/card requirements such as a build before commit.
- Mark code reviews as `code_and_focused_checks`. Keep risk classification,
  independent critical review slots and bounded rework unchanged.
- Add `reviews_approved` and VALIDATING between review and delivery approval;
  execute and bind the required project gate only after all code approvals.
  `review_approved` now accepts the final gate from VALIDATING, not REVIEWING.
- Require exact-base/head final gate records even without a project verifier.
  Reverify bindings and compare saved hashes on shipping, reusing valid proof
  without another gate run. Project profile selection remains opt-in/fail-closed.
- Use local state format 2 and preserve legacy format 1 receipts/checkpoints.
  Document evidence recovery and human stops for incomplete legacy deliveries.
- Distribution manifests and SHA-256 hashes are generated by install/update;
  no consumer installation, public release, merge or deployment is part of this preparation.
